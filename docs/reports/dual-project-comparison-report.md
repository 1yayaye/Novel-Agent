## 2. 真实安全策略与异常容灾测试 (Raw Novel Safety Evaluation)

在对用户指定的原著小说《我的妻子成了公司高层的公用奶牛》进行真实 API 调用探针时，发现了现代 LLM 商业 API 中的一个核心边界场景：**上游内容安全审核策略拦截（Content Safety Moderation）**。

### 实测表现追踪 (均配置 3 次重试)：
1. **第一章（职场压力与铺垫，无露骨两性描写）**：
   - **状态**: ✅ 成功（Attempt 1 即通过）
   - **耗时**: 9734 ms
   - **Token 消耗**: 输入 2317，输出 262，思维链推理 315 Tokens。
   - **提取摘要**: 成功捕捉“丈夫为换取升职加薪，在经济重压下拉拢妻子赴约陪同高层王总”的核心主线矛盾。
2. **第二章（含露骨成人性爱及敏感描写）**：
   - **状态**: ❌ 上游安全过滤拦截
   - **重试表现**: 连续 3 次调用，Google Gemini 均判定为 `HARM_CATEGORY_SEXUALLY_EXPLICIT`，直接返回 `choices: []`（空回）。
   - **两系统崩溃与容灾对比**:
     - **Project A（明月）**: `server.js` 第 247 行直接执行 `data.choices[0].message.content`，抛出致命异常 `TypeError: Cannot read properties of undefined`。前端 UI 处于死锁卡死状态，用户无法保存已生成的第 1 章进度，整个项目状态文件断流。

## 4. 重点质检对比分析

### 4.1 角色关系图 (Relation Graph) 提取质量
- **明月工具**: 依赖大模型在 Markdown 结尾手动打印 `[关系图JSON] {"nodes": [...], "edges": [...]}`。正则提取容易因为模型的文本插话或反引号代码块导致 `JSON.parse` 失败回退为 `{ nodes: [], edges: [] }`。
- **Novel Agent**: 通过严格 JSON Schema 强约束返回结构，保证提取出完整的角色关系网络。
  - **节点数量**: 7 个角色 (涵盖：李明、小静、王总、陈哥、小静母亲、女儿等)
  - **连线数量**: 11 条关系连线
  - **语义类型**: 准确解析了 `conflict`, `business`, `family`, `faction` 等复杂人际链条。

### 4.2 体系研判 (System Assessment)
- 本书为现代都市/职场潜规则/伦理情感小说，不存在玄幻战力等级或修真体系。
- **明月工具**: 依靠文本包含 `不处理` 进行正则匹配，容易发生语义歧义。
- **Novel Agent**: 模型通过 JSON Schema 严格输出结构化判定：
  ```json
  {
  "applicable": false,
  "label": "无",
  "reason": "本书为现代都市家庭伦理与情感犯罪题材，篇幅仅12章且已完结，职权变动仅为道德出卖的叙事对价而非规则驱动的晋升成长体系，无需建立体系表。",
  "fields": []
}
  ```
  系统自动将其标记为 `notApplicable: true`，且直接生成说明文案，完全免除了第 11 步无意义的 LLM 网络开销。

### 4.3 全书大纲生成 (Outline Candidate)
- **明月工具**: 不具备大纲提炼能力，作者必须自己手动阅读超级总结后自行提炼。
- **Novel Agent**: 依托全部已生成的账本资料自动生成标准大纲（前情、中段转折、高潮危机、结局走向），并可直接通过【应用至大纲】按钮一键同步至系统写作大纲中，实现真正的内容闭环。

## 5. 结论

本次实测表明：
1. 在遇到上游网络超时或偶发错误时，本次配置的 **3 次重试机制** 能有效抵御服务波动；
2. 当小说触及商业大模型的严苛内容安全过滤（NSFW）时，**Novel Agent（Project B）的错误隔离与事务保护体系展现出压倒性的工程防御优势**，彻底根治了明月工具崩溃闪退、丢失全书进度的设计缺陷；
3. 在正常分析流程中，**结构化 JSON Schema 与强类型校验**消除了标签漂移，并在非适用体系识别中实现了自适应短路与 Token 节约。
